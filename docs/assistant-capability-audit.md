# 对话助手接入核查（2026-09-26）

## 已确认的前后回答冲突

历史工具记录显示：第一轮分析两个账本，后续轮次只分析一个账本。第一轮汇总确有来源，并非虚构。恢复对话时前端没有恢复 analysisBooks；工作线程只传递问题和回答，不传递历史工具证据。模型因此把查询范围差异错误解释为旧数据不存在。

本次修改：打开对话恢复仍有权限的历史范围；发送时立即持久化范围；未传范围的客户端由服务端恢复；每条消息展示范围；历史上下文携带受权限过滤的汇总和记录 ID；接入系统全局搜索，支持 ID、金额、关键词、日期和分页，不改变统计范围。历史证据为快照，修改前必须重新查询。

## 系统操作接入

已接入确认卡：新账、原账修改/删除、退款、家庭往来、预算设置、周期计划创建、常用预设创建、费用分摊、分期购买/还款、记忆变更。查询接入账单、资产、分期、活动、家庭、记忆及跨账本全局搜索。

新增封闭操作目录 `assistant-operations.ts`，通过 `system_capabilities` 发现参数、`read_system` 查询、`prepare_system_action` 准备确认卡。覆盖钱包创建/修改/归档/恢复/合并/删除/余额校正，活动完整管理，分类增删改与排序，周期订阅编辑/暂停/确认/跳过/删除，常用预设编辑/删除，分期计划修改/撤销还款/删除，预算删除与取消分摊，账本创建/元信息/成员授权，家庭邀请/退出/转交/关联账本/权限/往来详情，回收站恢复/批量整理/凭证关联，个人资料/主题，记忆合并/拆分/重建/学习设置，报告管理、CSV 导出及后台任务查询/取消/重试。管理员可管理用户非秘密信息、队列及保留现有密钥的模型配置，并创建模型连接测试任务。

页面和助手共用 `application-api.ts`，权限、版本与业务限制仍由原处理器执行。用户确认时，已有业务事务使用当前确认事务的数据库连接，业务写入与确认状态一起提交；失败回滚，重复确认返回原结果。编辑钱包、活动、账本、分类、订阅、预设、家庭和资料时，服务端读取原字段并只覆盖指定值。卡片金额展示为元，嵌套金额也转换。仅能查看当前账本的用户仍可操作本人钱包，不能写入只读账本。

“接管”不等于绕过确认或授权。没有任意 SQL、URL、方法调用工具。密码、首次密钥配置、账号创建时的密码、文件上传/CSV 选择、退出登录仍由专用页面完成，`open_system_page` 在对话中提供可点击入口；不要求模型接触密码和密钥。导出提供经过权限校验的下载链接。当前对话自身的删除仍在历史列表操作，不能删除承载确认卡的记录。助手仍需要一个可访问账本作为对话容器。
