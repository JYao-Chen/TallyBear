# 费用归属与分担：完整功能设计

状态：设计稿，尚未实现或上线。基于 2026-09-27 的现有代码检查。本文定义通用功能，不创建用户的房租账单，也不替用户决定首尾月份。

## 目标和范围

用户可把交易记入个人或共享账本，再独立设置费用的期间归属、承担人和收入抵减。一次预付只扣一次钱包；多人分担不会复制付款；个人收入抵减只作用于指定受益人。

适用于季度房租、年费服务、课程费用，以及多人旅行或报销。继续使用现有 Next.js、TypeScript、PostgreSQL 和任务机制，不新增微服务，不引入复式会计科目系统。

第一版参与者支持本人及选定家庭内的已注册成员。家庭仅用于选人和结算权限，不限制来源账本。陌生用户邀请、跨家庭自动清算和自动换汇不在本版范围。

## 业务对象与关系

```text
个人账本或公账的原始交易 ─── 实际钱包收付款（既有逻辑）
          │ 指定参与金额
          ▼
       费用项目 ─── 可选关联已有活动
          │
          ├── 真实服务覆盖期
          ├── 各期费用归属 ─── 各成员承担
          ├── 补贴／报销收入 ─── 指定各期、各受益人抵减
          └── 已有家庭往来 ─── 实际结算进度
```

项目可含多笔付款，一笔付款可把不同金额归入多个项目。项目管理费用关系，不拥有第二套钱包，也不替代账本或活动。默认项目私有，只有主动邀请才产生共享。

### 三个统计口径

| 口径 | 日期依据 | 内容 | 是否影响余额 |
|---|---|---|---|
| 实际收支 `cashflow` | 原交易的实际发生日 | 支出、收入与退款；转账单列 | 原始交易影响一次 |
| 期间成本 `cost` | 约定费用归属期 | 未分摊普通费用 + 分摊费用，扣费用退款 | 否 |
| 个人净承担 `net_burden` | 承担与抵减的归属期 | 本人承担 − 本人已实现抵减 | 否 |

现有个人钱包实际收支继续表示现金流，不能悄悄改为净承担。成本口径中的家庭总费用与个人净承担使用不同名称，不以同一个“总支出”混称。

## 期间和金额计算

### 期间规则

- `immediate`：归到原消费当天。
- `daily`：按真实覆盖区间的自然日分配，保存开始日和排他结束日。例如 10 月 15 日至 1 月 15 日，覆盖至 1 月 14 日。
- `monthly_equal`：由用户选择明确的自然月集合，等额分配。真实覆盖期独立显示。
- `custom`：用户指定各期金额与起止日；同一来源片段内期间不得重叠。

月度成本在完整月份查询时显示整月值。查询周或指定日期时，将该月值按自然日确定性分配后取交集，前端标明“约定月成本按天折算”；不得把整月金额重复计入每个周。日报与月报求和必须一致。

一次性费用只有一日归属。不同来源可以有不同覆盖区间，汇总前先分别展开，不把项目首笔付款日期套给全部来源。

### 金额守恒

存储与计算沿用整数分。用最大余数法处理比例和尾差，排序固定为期间开始日、参与者稳定 ID；大数乘除使用 BigInt 中间值，接口输出检查后转为现有整数金额。

```text
每个来源的各期金额之和 = 该来源参与金额
每期各承担人金额之和 = 该期费用金额
每笔收入的各项目抵减分配之和 ≤ 该收入有效金额
同一实际付款的各项目参与金额之和 ≤ 该付款有效金额
```

月金额先定，再分配人员。指定总成员金额时还需保持列合计：使用剩余成员总额作为后续期间上限，最终一期补足；不能各期独立四舍五入导致人的总额漂移。自定义格子由用户填写，服务端同时校验行列合计。

同一交易在多个账本中的展示使用既有 `event_id` 去重；没有 event_id 的历史交易使用原交易 ID。来源可用金额检查必须跨项目并在数据库事务内锁定实际来源，不能只检查当前账本。

### 费用承担

承担方式支持仅自己、均分、比例和固定金额。项目内使用参与人作为承担对象，共同钱包也可对应明确的“家庭共同资金”承担主体。普通参与人不需要拥有来源账本权限。

按期变更成员或比例时，仅重算选定期间。已经确认的过去期间不能被默认覆盖；用户选择全期重算时展示前后差额并重新发起受影响成员确认。

### 抵减收入

补贴／报销仍是收入交易。关联记录保存收入中的参与金额、受益人和归属期，默认只抵减收入所有者的承担。

抵减到其他成员或共同资金，必须明确选择并确认共享。房补属于个人不代表必须抵减全家的费用。按月收入不自动等同于同月费用，归属期可手动指定，例如次月补发上月房补。

预计抵减只作为计划，不占用真实收入金额、不改变余额。到账后选择真实收入关联到原计划；计划转为已实现，不同时保留两份抵减。部分到账分别显示已实现和剩余预计。

允许抵减超过承担，显示负净承担和“补偿超过承担”，不截为零。若退款超过原消费，费用退款仅分配到可冲减费用的部分；剩余显示“超额返还”独立调整项，用户指定受益人和归属期。原退款流水金额和性质不自动修改。

## 结算计算

结算按整个费用项目计算，不把每月成本再次变成付款。月份筛选展示各期承担，结算区同时明确展示“全项目待结算”。

对参与主体 i：

```text
净承担 Bᵢ = 分担费用 Gᵢ − 分配给其的补贴／报销 Oᵢ
净垫付 Fᵢ = 实际对外付款 Pᵢ − 实际收到费用退款 Rᵢ − 实际收到抵减收入 Hᵢ
未结算余额 Qᵢ = Fᵢ − Bᵢ + 已确认结算转出 T_outᵢ − 已确认结算转入 T_inᵢ
```

Q 为正代表应收回，为负代表应补付。全部主体余额之和必须为零；来源尚未完整确认时只显示草案，不提供可确认的自动结算建议。预计收入不进入上述公式。

退款已在 G 中冲减，在 R 中记录真实收款，两者是承担与资金两个视角。个人收入抵减本人时 H 和 O 同时变化，不会改变另一个人的应付份额。收入抵减到别人时，会体现为收款人需要向受益人结算的金额。

共同钱包作为独立资金主体参与计算。个人向共同钱包的真实入金可按金额关联本项目，作用等同于主体间结算，不能把公共钱包全部付款认定为某个成员的垫付。未关联入金不自动抵本项目欠款。

复用 `family_movements` 的真实转账与到账确认，补充项目结算关联。一笔转账可以分配给多个项目，分配额之和不得超出转账金额；待收款人确认的记录不算已结算，并占用本次待结算额度防止重复提交。

已超额结算不丢弃，也不自动再扣钱；显示反向应收／应付建议。系统只准备结算，双方按照既有流程确认实际发生的资金往来。

## 房租示例与未指定的月份

用户付款 12,900 元，服务期为 2026-10-15 至 2027-01-15；原交易可保存在其个人账本。下面仅以用户选择归属 10、11、12 月为例，不能据此替用户保存该选择。

| 归属月 | 家庭费用 | 用户承担 | 用户已到账并关联房补 | 用户净承担 | 另一人承担 |
|---|---:|---:|---:|---:|---:|
| 10 月 | 4,300 | 2,900 | 1,500 | 1,400 | 1,400 |
| 11 月 | 4,300 | 2,900 | 1,500 | 1,400 | 1,400 |
| 12 月 | 4,300 | 2,900 | 1,500 | 1,400 | 1,400 |
| 合计 | 12,900 | 8,700 | 4,500 | 4,200 | 4,200 |

付款当日钱包减少 12,900；后续两个月没有由分摊生成的扣款。三次房补各到账 1,500 时才增加钱包。另一人共转入 4,200 后，付款人的全期净现金负担为 4,200。

尚未到账的月份不能显示“已实现净承担 1,400”，可同时显示预计净承担 1,400。9 月房补保持原到账日，除非用户明确关联，否则不自动搬到这期房租里。

首次设置必须让用户选择固定归属月份，或选择真实覆盖期按天分摊。若固定归属 11、12、1 月，公式相同；日分摊覆盖 10 至 1 月，首尾月不满额。持续租赁下一季度沿用明确的归属规则，提示重复覆盖或空档，不推断第一期的归属约定。

## 权限与协作

项目授权和原账本授权独立检查。参与人仅能读取已共享的项目数据；原交易详情始终通过原账本权限校验。管理员身份也不获得私有来源读取权。

| 角色 | 权限 |
|---|---|
| 项目所有者 | 编辑项目；邀请成员；准备期间／分担修改 |
| 已接受参与者 | 查看明确共享的项目与本人份额；确认或拒绝分担变更；关联自己的实际结算 |
| 来源所有者／有写权限者 | 关联自己可授权的来源；管理来源共享摘要 |
| 未受邀家庭成员 | 无项目访问权限；只有主动共享到家庭总览的摘要可见 |

邀请时预览共享名称、参与金额、期间和份额。私人订单号、备注、附件及钱包余额不包含在共享摘要中。收入抵减单独选择共享，不因分享支出而自动分享收入。

私人抵减仅进入本人净承担。家庭汇总只能显示已共享抵减，并标明“按共享数据”；不得通过总数、净额或导出来反推未共享收入。

参与者可选择把本人承担展示在自己的一个个人账本中。这是成本展示归属，不创建交易，不赋予项目所有者其账本权限。未选择时仍在“我的承担”可见。用户本人的原消费归属可沿用来源账本；另一参与者的成本由其自己选择归属账本。跨账本聚合按项目、期间和承担行去重。

邀请待接受期间属于待确认计划，不能当作对方已认可的债务。涉及他人份额的修改保存为待确认修订；当前已确认版本继续有效，全部受影响参与者接受后一次切换。自己的私人抵减不需要其他成员批准。

退出家庭后不能继续读取实时项目或接收新份额。本人已确认历史承担及真实结算保留最小个人历史快照，不包含其他人的来源数据；退出前提示处理未结算项目。历史未结清余额可查看但不再沿旧家庭权限发起新操作。重新加入也需新的邀请。

## 数据结构

以下是拟新增的业务表，不是已执行迁移。沿用 UUID、整数分、version 与 timestamptz 约定。

| 表 | 主要字段及责任 |
|---|---|
| `cost_projects` | id、owner_id、可选 family_id/activity_id、name、status、active_revision_id、version |
| `cost_project_members` | project_id、user_id、role、邀请状态、用户自选 display_book_id；共享摘要授权 |
| `cost_project_revisions` | project_id、version、draft/pending/active/superseded、规则 JSON、创建者、变更原因 |
| `cost_revision_approvals` | revision_id、user_id、accepted/rejected、时间；只记录受影响参与者 |
| `cost_sources` | project_id、transaction_id、实际事件标识、expense/refund/income、参与金额、付款／收款主体、来源版本、覆盖期、共享摘要 |
| `cost_periods` | revision_id、source_id、开始日／排他结束日、amount；服务端按规则生成 |
| `cost_shares` | period_id、user_id 或共同资金主体、amount；承担计算的有效结果 |
| `cost_offsets` | revision_id、income_source_id 可空、受益主体、归属期、amount、expected/realized；计划和到账关联 |
| `cost_settlements` | project_id、movement_id、参与金额；已确认状态从真实往来读取 |
| `cost_project_changes` | project_id、操作人、旧新 revision、原因、时间；不复制未授权私人正文 |

项目费用分类保存共享的项目分类标签，用户可为本人承担选择自己的分类 ID，不用某个人的分类 ID 冒充所有人的分类。共享展示名称与私有分类编辑互不覆盖。

期间和份额由同一个计算函数生成，客户端预览与后端保存使用同一输入契约。数据库中的有效结果仅由服务端写入，不能信任前端传入的总数。

来源交易修改、删除、退款和关联副本变更必须调用成本服务。金额变更影响已确认共享份额时，项目标为“来源变化待重算”，普通现金流照实更新；成本报表将受影响项单列为待核对，不把旧结果装成当前准确结果。重算确认后替换有效版本。

仅删除某账本展示副本不等于删除实际事件；只要授权来源仍存在，成本关联不丢失。最后一条真实来源撤销后才能将对应成本标为失效。移动账本后重新校验详情权限，不能沿旧链接继续开放来源。

## 接口与应用层

新增 `src/lib/cost-attribution.ts` 作为纯计算模块；新增 `src/server/cost-projects.ts` 处理项目权限与保存，`src/server/cost-reports.ts` 负责报表。数据修改仍由现有 API 入口分发，不新开服务。

| 拟定接口 | 用途 |
|---|---|
| `GET/POST /api/cost-projects` | 权限过滤后的分页列表；创建草案 |
| `GET/PATCH /api/cost-projects/:id` | 详情；以 version 更新草案 |
| `POST /api/cost-projects/:id/preview` | 返回期间、人员、抵减和预计结算，且明确 cashflowDelta=0 |
| `POST /api/cost-projects/:id/revisions` | 提交确认；共享变更进入待接受 |
| `POST /api/cost-projects/:id/respond` | 接受／拒绝对应版本邀请或修订 |
| `POST /api/cost-projects/:id/sources` | 关联真实交易的指定金额；可部分归入 |
| `POST /api/cost-projects/:id/settlements` | 关联真实往来或准备既有转账确认流程 |
| `POST /api/cost-projects/:id/archive` | 归档／恢复；不删除账单或结算 |
| `GET /api/cost-reports` | basis、scope、from/to、category、projectId、分页；返回口径说明 |

请求携带项目版本，重复提交复用现有请求 ID。来源占额、规则结果和审批状态在同一事务保存；多人共同使用同一来源时锁来源行。正常金额计算不依赖模型或异步任务。

禁止把新增日期口径直接塞进原交易金额字段。现金流接口保持原合同；成本与净承担可复用前端图表，但使用独立的数据查询和行类型。

### 报表去重和普通费用

期间成本 = 未进入任何有效分摊的普通净费用 + 已生效期间费用。只分摊部分金额时，原交易剩余金额仍留在实际发生期作为普通费用。关联退款按对应部分处理，不能减去全部原订单。

项目模式、账本模式和个人模式分别声明范围。项目汇总以项目来源去重；账本成本只包含该账本归属的原费用或本人选择展示的承担，不能把同一项目原总额与本人份额相加。多人承担视图优先使用承担行，原单仅作引用。

个人净承担的默认范围是本人；单人普通支出按本人承担，未设置成员分担的公共钱包消费不猜测到个人，显示“共同资金／未分配”。选定家庭汇总只使用已共享项目和允许查看的普通成本，明确未分配金额。

净承担报表已经抵减的收入不能在同一“净负担”合计里再次扣除。独立现金流收支结余仍照常包含全部实际收入。预算第一版保留原口径并标注“实际支出”，不随用户切换成本视图悄悄改变超预算判定。

## 页面和操作流程

### 记一笔与账单详情

现有手动记账、AI 草稿和助手卡片都提供可选的“费用归属与分担”。不开启时保持现有流程。

按“原始付款 → 期间归属 → 成员承担 → 可选抵减 → 预览确认”顺序编辑。每一步只展示有关字段。保存一笔新交易并创建项目草案应原子完成，失败不能产生“账单已入账但用户以为全部失败”的重记风险。

确认页分成“本次真实资金变化”和“费用分析设置”。只有原始交易或新的真实结算才能在前一区域出现扣款；分摊保存显示“仅更新费用归属，不再次扣款”。

### 计划与分摊

将原“费用分摊”升级为“费用归属与分担”。列表可筛本人、参与项目、待确认和已归档；搜索名称，按分类与期间过滤。默认分页 20 条。

项目详情分成概览、期间与成员、抵减收入、结算、变更记录。桌面以期间表格查看成员份额，手机按月份展开纵向内容；月份和成员很多时独立分页，不把几十列压到手机上。

本页操作包括关联已有付款、关联到账收入、设置未来预计收入、调整后续期间、邀请成员、准备结算、归档与恢复。删除仅允许无确认来源／结算的草案；已有项目使用归档或明确撤销分析关联，永不连带删除原始流水。

### 收支分析与个人账本

增加“实际收支／期间成本／个人净承担”选择，所有图表、汇总、导出和下钻同时使用选定口径。切换保留日期范围，移除不适用的钱包过滤并提示；成本按承担人过滤，不能沿用付款钱包筛选而漏掉他人垫付。

成本明细显示归属期间、本人份额和可查看的来源；个人账本中的承担行标注“分摊记录，不扣钱包”，点击进入项目。无原账本权限时仍能查看共享摘要，原账单详情按钮不可用。

净承担分开显示承担额、已到账抵减、净承担和预计净承担。家庭总额只用家庭可见数据；私人抵减仅在本人视图出现。

资金资产始终显示真实流水。可以跳转查看相关费用项目，但不把分摊行当成钱包交易。中英文标签与帮助文档在功能交付时同步；本设计稿暂不加入面向用户的已上线功能清单。

## 搜索与助手

全局搜索增加费用项目结果，复用项目权限和共享摘要，不检索未授权来源。点击搜索结果进入对应项目或期间，沿用已有分页。

助手工具复用上述服务，提供读取项目、预览分摊、准备创建／修订、准备抵减关联、准备结算和归档确认。`read_system` 与 `prepare_system_action` 能力目录同步更新；助手不能通过原始 SQL 绕过权限。

识图只抽取付款事实。看到“季度”“年费”等可提出分摊建议，不能自行创建成员债务或分享私人账单。用户没有明确选择固定归属月份时，助手询问该选择；不能把 10 月 15 日静默当成 10 月 1 日。

助手确认卡显示真实付款、归属规则、各人份额、已实现／预计抵减与共享范围。修改已有项目保留项目 ID 并检查版本；最终回答只能说明确认卡已准备，不能在用户未确认时声称已分摊或已结算。

## 旧数据接入和发布

1. 先实现纯计算及隔离数据库测试，不改生产。
2. 新增项目数据表和服务，普通记账仍走原路径。已有分摊继续正常读取。
3. 提供一次性的显式转换命令：按真实事件整合旧 `expense_allocations` 和 `family_expense_shares`，保留原金额、覆盖月份及已确认往来。重复展示或相互矛盾设置列入待核对，不自动选一个覆盖。
4. 转换记录用唯一旧来源 ID 标记，防止重复转换。被转换来源在新旧成本查询中只能选一条有效路径；这仅用于本次历史接入，不建设通用迁移框架。
5. 完成所有调用入口切换，包括原分摊编辑器、AA、周期收支自动分摊和分期成本。旧接口不得继续独立写入一套不联动的数据。
6. 隔离恢复库对比转换前后实际交易与钱包余额；旧分摊成本在未改规则时保持一致。
7. 备份后执行增量表结构和历史转换，再发布前后端。保留旧表供回退，不删除原账目。代码回退后新项目不可编辑，并明确旧版统计不包含新创建项目；不能声称回退后功能完全等价。

实施依次交付计算与数据、私有项目、共享与结算、全局报表与助手、历史接入。每阶段标明可用范围，只有全部验收通过才称功能完成。当前设计不授权自动发布生产。

## 验收样例

| 场景 | 必须得到的结果 |
|---|---|
| 房租个账付款 12,900，三个月，份额 8,700/4,200，每月个人房补 1,500 | 家庭月成本 4,300；到账后个人净承担各 1,400；只有付款日扣 12,900 |
| 同样房租存于共享账本 | 分摊与结算数值相同；不新增第二次扣款 |
| 第二个月房补未到账或只到 1,000 | 已实现与预计分开；收到多少钱包才增加多少 |
| 房补发给 A，但明确共同受益 | 抵减按约定分配，收款与受益差额体现在结算中 |
| 10 月 15 日至 1 月 15 日按日分摊 | 四个自然月有成本，合计严格等于原额，首尾不满额 |
| 年费 100 元分给 12 月和 3 人 | 所有期间与人员合计守恒，重复读取尾差位置不变 |
| 订单 1,000 仅 600 参与分摊 | 普通当期费用 400；600 按期归属；无重复 |
| 同事件在两个账本展示 | 资金与成本都只计算一次；删除一个副本不丢关联 |
| 两个项目并发关联同一收入剩余金额 | 只能在可用金额内保存，不超额抵减 |
| 分摊后退款、超额返还或修改源金额 | 真实余额照实更新；成本按明确规则调整，冲突项可见 |
| 一人垫付、多笔部分结算、结算后调整份额 | 已确认转账保留，剩余欠款或反向退款建议准确 |
| 家庭公共钱包支付、成员向公共钱包入金 | 不将全额归为某个人垫付；入金只计算一次 |
| B 无 A 个账权限但接受共享分担 | B 看到自己份额，不看到 A 私人来源、钱包及未共享房补 |
| 拒绝邀请、撤销原账本权限、退出家庭 | 不再授予实时源数据访问；本人已确认历史按约定保留 |
| 修改版本期间刷新或重复提交 | 不重复创建付款、项目或结算；待确认修改不覆盖有效版本 |
| 周／月／自定义日期查询、分页和导出 | 同口径加总一致，行合计与图表一致 |
| 助手修改已存在项目 | 正确更新确认卡，保存前无账务写入，无重复项目 |
| 360/390px 手机与桌面，中英文 | 表格、按钮不溢出；口径标签完整；长列表分页 |

权限、余额不变性与金额守恒属于发布必过项。UI 测试覆盖新建、修改、到账关联和结算的完整路径；本设计阶段未运行实现测试。
