# 智能财务记忆：功能边界、历史初始化与发布验收

本功能已接入识图、文字记账、助手和全局搜索，并通过用户要求的 5 个真实模型验收案例。它不微调模型、不增加独立服务，也不自动修改历史账单。代码发布与历史初始化是两个步骤，不能把“已上线”当作“历史整理已完成”，小样本通过也不代表总体准确率。

## 入口和处理链

- 个人资料 → **记忆中心**独立栏目：以完整页面管理记忆，不再使用弹窗。助手输入区和全局搜索中的记忆入口跳转至同一页面。
- 页面分为“我的记忆／待确认／变更记录／学习与设置”；支持类型、状态筛选和分页。宽屏列表与详情并排，窄屏选中后显示详情，可返回列表。
- 草稿与助手待确认卡：商品记忆候选、关联状态、依据、不是同款、仅本次不使用；超过 6 个候选分页。
- 全局搜索：新增“记忆”类型，搜索名称、别名、正文；商品详情和购买来源在记忆中心查看。
- 管理员：个人资料 → 记忆中心 → 学习与设置 → 记忆模型配置与运行统计。

```text
确认账单／完成对话 → 数据库 outbox → 现有 memory 后台任务
                                          ↓
                           私有商品／偏好／来源版本／向量
                                          ↓
识图草稿／助手 → 权限限定 → 精确、关键词、向量检索 → 候选判别
                                          ↓
                           可编辑建议 → 用户确认 → 入账
```

`src/server/memory.ts` 提供统一检索和管理接口；`memory-worker.ts` 处理来源学习、历史整理、向量重建。原分类加权仍作为分类建议的兼容路径；它尚未完全由统一记忆规则替代。

## 已实现的边界

- 商品关系与支付记录分离；明细使用稳定 UUID。来源记录版本失效或权限撤销后不再作为可用证据。
- 精确名称／别名匹配、至多 20 个关键词候选与 20 个向量候选、排名融合、最多 8 个判别候选。未配置模型时继续精确／关键词建议。
- 在线商品检索模型调用共用每次建议请求 12 秒预算；模型请求自身上限 30 秒。超时不影响正常账目保存。该预算不是整批 OCR 的总超时。
- 商品属性由提炼模型抽取规范名称、品牌、型号、规格及原文引用。引用必须在商品原文中存在；缺少规格不臆测。后台分批处理并缓存提炼步骤。
- 旧手工账单没有商品摘要时使用具体标题；仅有“交通”等分类或店名不会强行推断商品。配送费、优惠不当成商品。删除旧来源后重算仍有效来源的分类、商家和平台；明细重排不改变关联。
- 逐字段建议覆盖商品摘要、标题、商家、平台、分类。已明确输入的稳定事实保留并提示差异；缺失字段自动填入，模型推测分类可由明确规则／同款记忆替代。每个字段显示修改前后值，支持单独采用、保留或撤回；撤回不会覆盖之后手动修改的值。
- 新价格、数量、日期、支付编号、钱包和活动归属不能从旧订单自动复制。多商品按明细 ID 关联，不用某件商品替代整单摘要或商家；有未关联明细时整单分类需核对。
- 同一作用域的矛盾分类规则默认保存为待确认；明确选择“替代同一场景旧规则”后才停用冲突旧规则，保留事件记录。个人明确规则优先于家庭规则。
- 用户可管理别名、品牌、规格、规则范围、活动／周期账单／预设引用；可停用、合并、按来源拆分、导出、遗忘。保存和状态变更支持版本检查与撤销；合并／拆分不支持一键撤销。
- 共享生成独立条目，不复制私有证据、业务引用和钱包。家庭成员资格实时检查；管理员不能读取其他用户私有正文。
- 遗忘清除正文、向量和来源，保留来源排除标记；“允许重新学习”会清除本人的全部排除标记。
- 对话只提炼用户原文中可引用的内容，普通提炼进入待确认，明确“记住”且不是疑问／假设的内容才启用；助手回答不作为财务事实。仍需真实模型测试误提炼率。
- 商品详情按当前可访问来源计算购买次数、已知金额和未知金额条数；不会将整单价格冒充某件商品价格。尚未实现价格趋势图或明细退款分配。
- 历史任务保留游标与提炼结果检查点；关闭个人学习会暂停后续整理，开启后从后台任务重试。保存账目不等待任务。

## 数据与向量配置

`npm run db:init` 依次执行原 `scripts/schema.sql` 与增量 `scripts/memory-schema.sql`。新增记忆表，不删除旧账务字段；只给缺少 ID 的历史明细补 UUID，不改变金额／分类／钱包／退款。

pgvector 必须安装在与当前 PostgreSQL **相同主版本**的运行环境中，然后由有权限的运维人员在目标数据库执行 `CREATE EXTENSION IF NOT EXISTS vector;`。初始化脚本不会替换生产数据库镜像或卷。未安装扩展时向量查询降级为关键词查询。

向量存为 PostgreSQL 数组，查询时转为 `vector` 执行精确距离排序，不建近似索引。默认在首次使用时复用官方 DashScope 地址的现有助手／识图加密密钥，无此配置时读取 `DASHSCOPE_API_KEY`，沿用 `ENCRYPTION_KEY` 加密保存。不会把第三方代理密钥发送给阿里云；不会覆盖已有独立记忆模型配置。

默认嵌入为 `text-embedding-v4`、1024 维；提炼与判别分别配置，默认均为 `qwen3.8-flash`，关闭思考、请求 JSON 输出。三个用途仍可在管理员界面单独覆盖。密钥不返回前端；可查看连接测试与近七天调用数、失败数、延迟及可获得的 token 数。接口依据：[阿里云嵌入接口](https://help.aliyun.com/en/model-studio/embedding-interfaces-compatible-with-openai)、[Qwen3.8-Flash](https://help.aliyun.com/zh/model-studio/qwen3-8-flash)。

更换嵌入模型后，按用户重建新版本，全部当前内容完成后才切换该用户的活动版本。旧模型配置与旧向量保留以支持过渡，不混算不同维度。尚无管理员一键为全部用户批量启动重建的界面。

## 可重复验证

所有集成脚本必须使用隔离数据库，不能加载生产 `.env`。

```sh
npm run typecheck
npm test
# DATABASE_URL 必须以 _memory_test 结尾
npx tsx scripts/memory-smoke.ts
# 另需测试专用 ENCRYPTION_KEY；模拟模型服务，不调用真实厂商
npx tsx scripts/memory-model-smoke.ts
# 需先启动测试服务器，设置 PLAYWRIGHT_MODULE、TEST_ORIGIN、TEST_ARTIFACT_DIR
node scripts/memory-browser.mjs
# 使用真实 DashScope API，合成数据，不读取生产账单；需测试 ENCRYPTION_KEY 与 TEST_ARTIFACT_DIR
npx tsx scripts/memory-live-five.ts
# 需 LIVE_REPORT 指向上述 live-five.json，沿用浏览器环境变量
node scripts/memory-fields-browser.mjs
npm run build
```

已在 PostgreSQL 16.14、pgvector 0.8.2 的隔离数据库检查来源学习、权限隔离、拒绝关联、遗忘、账务不变、共享退出、合并／拆分保持、助手准备不写入、索引切换与降级。备份恢复至第二个隔离数据库后，交易金额／数量、记忆／来源／向量数量及扩展版本一致。浏览器覆盖记忆中心保存与 360／390／1280px 无横向溢出，不代表所有复杂草稿界面已完整回归。

用户已将真实模型验收从 100 案例改为 5 案例。`scripts/memory-live-five.ts` 固定覆盖：苹果云空间与 iCloud 同义召回、GPT Pro 不关联 Plus、同款新价格且字段撤回、多商品明细分别关联、偏好冲突与明确替代。种子账单通过真实后台属性提炼与向量生成，再走生产同一检索／判别函数。5/5 通过；第一次运行发现重复规格导致误拒绝，修复后保持相同案例重跑通过。样本是合成账目，使用真实 `qwen3.8-flash` 和 `text-embedding-v4` API，不是模拟模型，也不是生产数据上的总体准确率结论。

## 历史初始化与运行

生产发布后，由运维在已发布版本目录、使用生产环境运行 `node scripts/memory-history.mjs --enqueue`，为允许学习且有历史来源的用户加入普通后台整理任务。`--status` 只输出队列及条目数量，不展示私有记忆正文；关闭学习的用户不被强制开启。也可由用户在记忆中心点击“整理历史”。

任务只新增记忆、来源及向量；历史金额、分类、钱包、订单编号、退款及交易数量保持不变。明细 ID 初始化保留原修改时间。处理失败可在任务列表重试，沿用游标和已完成提炼步骤；不应重复提交全部历史任务。上线后应确认任务完成、向量版本启用，再把历史初始化标为完成。

## 已验证与尚未覆盖的范围

1. 本轮要求的默认模型接入、商品属性自动提炼、逐字段填充／撤回、规则冲突处理和 5 案例验收已实现。
2. 原大方案中的商品价格趋势图、管理员跨用户批量重建仍为后续范围，不在本轮 5 案例验收内。
3. 来源删除重算和多明细重排已补充集成验证；完整助手端到端确认、复杂卡片移动布局与英文文案仍有扩展空间。
4. 发布须按生产 README 备份数据库、验证 pgvector 安装与同主版本恢复，再发布新 release、启动历史整理。回退代码不删除新增记忆数据。

真实模型验收仅使用合成账目。生产历史整理与部署记录保存在生产运维目录，不把真实账单或密钥提交到仓库。
