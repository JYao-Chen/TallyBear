# 个人画像与上下文：实施范围

目标：以动态、可解释的个人画像取代记忆中心的使用方式；保留商品、来源、语义检索和遗忘能力。画像不替代账务事实、不自动入账，也不推断与财务无关的敏感属性。

## 已实现

- 入口为个人资料 → 个人画像，包含总览、场景规则、商品服务、长期安排、待确认、学习记录及隐私设置。
- 全部有效个人账目按实际事件去重；当前权限、遗忘、删除及他人纠正实时过滤。
- 支持场景条件、逐字段权重、近期变化、衰减和反例。明确规则优先，但不覆盖本次明确输入或相冲突的付款证据。
- 可确认、纠正、停用或排除建议；草稿可撤回填充，规则可撤销和导出。原商品管理的遗忘、合并拆分及家庭共享继续保留。
- 浏览器定位按需授权、降低精度、失败可手动选择；录入位置与消费地点分离，发送后清除本次区域选择。
- 消费区域关联需另行开启保留。关闭保留会删除关联；清除位置还会删除区域及其规则。坐标不进入账单、后台记账任务或外部模型。
- 识图、文字记账及助手确认卡共用建议服务。全局搜索支持本人明确规则，助手修改规则仍须确认。

## 权重和动态更新

画像读取本人创建、仍可访问的有效收入与支出。每个字段单独判断，权重按交易日期每 60 天衰减一半，编辑旧账不会使其重新变成近期消费。明确纠正乘以 3；未经手动确认的自动填充乘以 0.35，不计为独立偏好。

稳定建议要求至少 3 笔独立支持，加权占比达到 85%，有效权重至少 1.5，并覆盖对应场景至少 60% 的记录。近 30 天与此前倾向发生变化时保留候选。超过 120 天没有该字段依据的习惯不自动填充。支持占比不代表预测准确率。

画像在读取和生成草稿时基于当前数据计算，不维护旧的统计快照。商品提炼和向量生成仍复用原后台任务。缺少交易时间就不匹配时段，不用提交时刻伪造购买时间。

## 规则和位置存储

规则可以限定商家或消费场景，以及日期类型、时段和已保存区域。所有条件同时满足才生效。同场景冲突替换需确认；同样明确的不同规则只产生候选。重复确认相同规则不会创建重复条目。版本检查和变更记录防止旧操作覆盖新规则。

位置默认关闭，登录和展开设置不会读取定位。点击定位后，浏览器和服务端均将坐标降低到 0.01 度，区域至少约 1.5 公里。区域由用户命名，不推断住宅或工作地址。多个区域都匹配时不擅自选择。使用位置时还需确认是本次消费发生地。

`/api/personal-profile` 提供总览、规则、来源和设置接口，支持变更、撤销及导出。新增表在 `scripts/profile-schema.sql`，由现有初始化流程运行。原账单金额、日期和钱包余额不变；发布需先执行包含该文件的初始化流程。

- `scripts/profile-smoke.ts` 在隔离数据库验证规则持久化、权限、坐标过滤、关闭学习、清除位置和账务不变。

- `scripts/profile-browser.mjs` 使用真实页面组件与模拟接口，覆盖中英文 390／1440px 截图、规则保存和停用、商品页面及学习开关。
- `scripts/profile-location-browser.mjs` 验证显式定位点击、拒绝权限后的手动选择、粗粒度处理和消费区域确认。
