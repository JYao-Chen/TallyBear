2026-11-22，基于 main `4487483` 源码，并用一份真实库的只读汇总核对过各问题确实存在。仓库公开，本文不含任何真实金额；带数字的版本只留在维护者本机（`STATS-AUDIT.md`，已被 .gitignore 排除）。

## 2. 问题（按严重度）

### P1 会让结论出错

1. **家庭钱包的支出不归任何人。** `personalExpenseReport` 的归属链最后一步是 `a.owner_id`，家庭钱包的 `owner_id` 恒为 NULL（约束 `accounts_asset_owner`），没有认领时整条 COALESCE 为 NULL，于是这笔支出不进任何人的“我的费用”。真实数据中这类支出全部落空。家庭层面也没有“家庭费用”报表来接住它们。
   位置：`src/server/reports.ts` `personalExpenseReport` 的 `filter.where`。
2. **余额校准是一个不可见的大口子。** 校准金额在 E 里只是 `adjustment`，不进 A/B/C/D 的收支；D 的“净支出/收入”和余额变化因此对不上，且没有任何地方提示“有多少钱没有解释”。集中校准通常意味着那段时间漏记较多。
   位置：`server/wallet-funds.ts`；`accountReport` 不读 `account_adjustments`。
3. **同名“净支出”两种口径。** A 是分摊口径（预付年费按期摊、信用卡消费当期计），D 是现金口径（按付款日、按钱包）。前端分别显示为“净支出”，用户无法判断看的是哪一个。预算用的是 A。
   位置：`components/BudgetPanel.tsx`（`kind=net_expense`，默认分摊）；`components/AccountStatistics.tsx`（`summary.expense-summary.refund`）。
4. **D 同一屏三个数关系不明。** “净支出”含信用卡消费，“现金实际支付”= 现金钱包消费 + 信用卡还款，“负债账户消费”是信用卡消费。还款对应的是以前月份的信用卡消费，三者既不相加也不相减，界面没有关系式，容易被当成“现金实际支付 + 负债账户消费 = 净支出”。
   位置：`server/accounts.ts` `cashPaid`、`debtPurchases`。

### P2 口径不一致，容易误读

5. **赠与三种算法。** A/B 只在私人账本视角计收支（`movement-report.ts` 的 `personal_scope`），D/E 在“对方不是所选钱包”时计收支。同一笔赠与在账本报表里可能是转账，在资产页是支出。
6. **活动报表不分摊、不走认领链。** F 直接按交易日取整笔，预付型活动费用（如年卡）在活动里一次计满，与 A 不同；也没有用 B 的归属，个人活动看不到“自己承担多少”。
7. **余额校准按录入时间入账。** E 用 `created_at` 的上海日期，补录上月的校准会落进本月，月度期初期末都偏。
8. **预算不延续、只限单账本。** `budgets(book_id,month,category)`，每月需重建，漏建的月份首页预算卡无数据。跨账本的个人预算（我在共享账本里的份额）无法表达。
9. **共享账本的个人份额依赖手工认领。** 共享账本里由个人钱包付款、没有建认领的部分在 B 中全额算付款人，对方为 0。界面没有“未分账”提示。
10. **`min/max` 按整单金额筛选，合计按 `matched_amount`。** 按分类筛选再加金额区间时，区间判断用的是整单金额，结果与列表显示的计入金额不一致。
    位置：`reportFilter`。

### P3 精度与维护

11. 金额在 SQL 里转 `float8` 返回，前端再加减；目前规模无误差，但合计、导出应保持整数分。
12. 明细合计与整单不符时，分类按权重缩放到整单，结果正确；商品报表（G）用明细原值，两者会有差额。录入时应提示“明细合计与实付不符”。
13. `unified-expenses.ts` 在循环里逐条查询（每个来源、每个旧分摊各几次），账本或分摊增多后报表变慢；统一口径的投影应成为一张可索引的物化表或视图。
14. 同一套“去重 + 分类拆分 + 退款取负”在 `reports.ts`、`activities.ts`、`accounts.ts`（JS 版 `categoryAmounts`）各写一遍，SQL 与 JS 两份实现靠注释保持一致。

## 3. 能否清晰洞察财务状况

现状回答不了三个基本问题，或者要用户自己在不同页面拼：

- **这个月我花了多少？** 有 A、B、D 三个数，口径不同、名称相同。
- **钱从哪来、到哪去？** E 有完整资金流，但不在首页，也不和消费数对账。
- **我现在有多少钱、比月初多还是少？** D 有净资产，但没有期初，变化里混着未解释的校准。

## 4. 建议：一个“财务总览”，三条线加一张对账表

| 线 | 定义 | 数据源 |
|---|---|---|
| 消费（我承担的） | 分摊口径，按归属人；家庭钱包支出为“家庭共同费用”，在家庭视图统计，个人侧以“家庭缴款”体现 | 统一投影表 |
| 现金流 | 现金钱包的实际流入流出，信用卡只记欠款变化 | 钱包流水 |
| 净资产 | 期初、期末、变化 | 钱包余额重建 |

对账表（本期）：

```
消费
 + 本期付款但计入未来期的（预付、分期未摊）
 − 以前付款、本期摊入的
 + 信用卡本期还款 − 信用卡本期新增消费
 + 替别人付、待收回的（认领未结） − 别人替我付的
 = 现金净流出（消费部分）

收入 − 现金净流出 ± 家庭往来 ± 余额校准（未解释差额，单列） = 净资产变化
```

“未解释差额”单独成行并给出入口去补记；它为 0 时财务状况就是对得上的。

界面规则：所有金额旁的口径标签只有两种——“按归属期”和“按付款日”；“净支出”一词只用于前者。

## 6. 已定：家庭钱包按“缴款 + 共同费用”

2026-11-22 确认。使用方式：成员每月定期转入家庭钱包，日常从里面扣费。

- 家庭钱包支出默认是“家庭共同费用”，不进任何人的“我的费用”；在家庭视图按分类统计。
- 成员转入家庭钱包记为“家庭缴款”：个人现金流单列一行，不算消费；家庭视图按成员列缴款、共同费用、结余。
- 某笔实为个人的支出，用认领指给该成员（现有归属链已支持）。
- 统一缴款记法：现有数据中转入家庭钱包既有记为家庭往来的，也有记为普通转账的，两种在各报表处理不同。阶段 1 迁移为同一种（家庭往来 `kind=contribution` 或等价标记），旧数据回填。
- 第 2 节 P1-1 据此修正为：补“家庭视图”报表接住共同费用，而不是把它分给个人。
