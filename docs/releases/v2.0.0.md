# TallyBear 2.0.0

2026-09-27 · Personal and family bookkeeping with financial memory.

2.0 brings together the changes developed after 1.5. Package metadata, the lockfile and Compose image names use `2.0.0`. See the [version history](../version-history.md) for earlier milestones.

## Daily use

- Unified Spending analysis with charts, keyword filters, paginated records and year/month/week/day/custom ranges.
- Independent personal and family wallets; personal-wallet reporting across books and asset charts.
- Cross-book activities with types, optional family participation, budgets, archive/reactivation and transaction-preserving deletion.
- User-owned category catalogues and feedback-based classification suggestions.
- Cross-book original-purchase search for refunds, editable field reuse, multiple refunds and cashback exceeding the original payment.
- Optional order/payment references, separate date and time fields, long-image order assembly, and independent product/discount/fee sections.
- Unit-price × quantity suggestions, preserved manual subtotals and explicit adoption of a recommended payment total.

## Assistant and memory

- Persisted conversations and query scope, background jobs, grounded cross-book lookup and confirmation-based transaction changes.
- Permission-checked management operations across supported wallets, books, families, activities, plans, categories, reports and memory.
- Revised card hierarchy and distinct edit/confirm/cancel operations. Processing hints stay outside transaction notes; replaced pending drafts can be cancelled during a confirmed draft merge.
- Product attributes, source evidence, aliases, field-level suggestions, conflict review, private/shared memory, forgetting and historical organization.
- Independent receipt, assistant, embedding, extraction and judgment settings. Optional pgvector retrieval, with keyword fallback.

## Interface and documentation

- Full-page memory management under Profile; family movements in the entry workspace; responsive navigation and paginated lists.
- Receipt editor pages hold three items; read-only detail pages hold six. Summaries include all pages.
- Rewritten English and Chinese READMEs, separate galleries for each language, and desktop and mobile screenshots.
- The Docker runtime now includes `memory-schema.sql`, required by initialization.

## Upgrade notes

Back up the database, receipts and configuration together. Keep existing volumes, the PostgreSQL major version and `ENCRYPTION_KEY`. Both schema scripts must run before starting the updated web and worker together. Installing pgvector and organizing historical memories are separate steps. Follow [deployment instructions](../deployment.md).

## Known boundaries

Transaction/global search is keyword-based; vector lookup applies to memory. Price-trend charts, automatic currency conversion and unrestricted assistant administration are not implemented.
