# TallyBear 2.0.0

2026-11-22 · A rebuilt interface on a reorganized server.

2.0.0 keeps the product's accounting rules, permissions and data, and rebuilds how it looks and how it is put together. It includes everything from the [2.0 preview](v2.0.0-preview.md). Upgrade steps and the migration list are in [deployment](../deployment.md#upgrading-to-200); the full list of changes is in the [changelog](../../CHANGELOG.md).

## Find things faster

- Five destinations: Home, Records, Analysis, Wallets & plans, Family. Settings, help and your profile sit under the account menu; the assistant and the book switcher are always at hand.
- Every page, tab and detail view has an address. Back, refresh and shared links land where you were.
- On phones, a bottom bar with a central "record" button; on desktop, a sidebar.

## One look across every page

- A single set of colours, type sizes, spacing and components, shared by the bear and minimal themes.
- Lists, cards, detail sheets, filters, pickers and confirmation dialogs behave the same everywhere. Destructive actions are visually distinct and ask before acting.
- Every chart and figure was checked against the underlying records: Home, budgets and analysis report the same month; wallet totals equal assets minus liabilities; the family overview reconciles contributions, shared costs and balance.

## Numbers you can rely on

- Amounts are computed in integer cents with one spending projection for all reports.
- Family wallets are reported as contributions and shared costs. Contributions no longer appear as personal transfers out, and family-wallet payments count once, as shared family costs.
- Balance corrections take effect from the date you set.

## Safer assistant

- Assistant actions are graded. Reading and ordinary entry are automatic; deletions, permissions, family membership and balance corrections always become a card you confirm.
- Every assistant action is logged, and new or edited entries can be undone.

## Under the hood

- Numbered database migrations with checksums; existing installations are recognised and upgraded in place.
- Domain API routes behind one request wrapper, with error codes.
- Digest-stored sessions, per-IP login throttling, an 8-character password minimum and push-based job progress.
- Formatting, linting, database and smoke test suites, and characterization tests for the accounting rules.
