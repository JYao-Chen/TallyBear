# Delete an extra wallet entry

Ordinary transaction entries in Wallet cash flow now expose **Delete this entry** in their detail sheet, both from the main list and daily drilldown. This covers income, expense, refund and own-wallet transfers. Family movements and balance adjustments retain their separate management rules.

Deleting a wallet payment is different from removing its appearance in one book. This operation moves all currently live copies of the same financial event into their existing book recycle bins. Their attachments and metadata remain intact. Wallet balances and cash-flow statistics recalculate from the surviving events. An internal transfer is removed from both wallets; this does not reverse any real bank/payment transaction. Restoring a deleted book copy later restores the event's financial effect.

`GET /api/assets/funds/entry?id=...` returns deletion eligibility, a linked-copy count and the source version and live-copy count, without disclosing private-book copy identifiers. `DELETE` accepts that expected version and copy count and soft-deletes in one transaction after locking related books. The actor must manage every involved personal/shared wallet; this allows the actual payer to clear their own funding event even when a linked display copy belongs to a recipient's private book, without exposing that book's contents. Recipients cannot remove another person's funding record. Account archival does not prevent removal of historical erroneous records.

Active refunds, cost-project sources and family settlements block deletion with a reason. Existing source-deletion triggers withdraw pending/accepted claims and their managed copies. Stale previews require a reload. A confirmation explains the scope before any mutation. After success, main and daily lists, wallet summaries and parent account/analysis views refresh.

No schema migration is required. `tests/wallet-entry-delete-db.test.ts` covers both wallet balances for an internal transfer, linked-book removal, wallet permissions, stale previews, refund blocking and accepted-claim withdrawal using a disposable local `WALLET_DELETE_TEST_DATABASE_URL`. `scripts/wallet-entry-delete-browser.mjs` checks the real components with synthetic API responses at desktop/mobile widths, confirmation cancellation, the deletion payload, refresh and conflict/permission feedback. Development verification does not delete production records.
